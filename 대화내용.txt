GitPython  최대한 라이브러리 많이쓰는거 써서 안전하게하자

GitPython 쓰는 게 subprocess보다 예외 처리와 상태 확인이 훨씬 안전합니다. 그 버전으로 git 부분을 교체하겠습니다.

명령 4개 실행함, 파일 수정됨, 파일 공유함
GitPython 기반으로 교체 완료했습니다.

subprocess 대비 개선점
저장소 유효성 — InvalidGitRepositoryError, bare 저장소, detached HEAD 각각 구분해서 안내
변경 감지 — is_dirty(untracked_files=True)로 변경 없으면 빈 커밋 안 만들고 스킵. 수정/신규 파일 목록도 로그에 표시
push 결과 해석 — 플래그로 성공/에러/거부를 판별. 특히 원격이 앞선 경우(REJECTED) "git pull 먼저 필요"라고 정확히 알려줌
upstream 자동 설정 — 첫 푸시도 set_upstream=True로 처리
인증 실패 — GitCommandError의 stderr를 잡아 원인 표시

한 가지 참고: GitPython도 실제 push 인증은 시스템 git credential을 그대로 씁니다. 그래서 최초 1회 수동 push로 PAT 토큰을 credential store에 저장해두면, 이후 프로그램에서 자동 푸시됩니다.

WP 포스트 하단 후크에 넣을 코드:

html
<div id="tbw-widget"></div>
<script src="https://당신프로젝트.pages.dev/widget.js"
        data-container="tbw-widget"
        data-title="함께 보면 좋은 글"
        data-max="10"
        data-shuffle="false"></script>
옵션 설명:

data-max — 노출 개수 (10)
data-shuffle="true" — 매 로드 랜덤 (같은 방문자에게 다양하게 보이고 싶을 때)
data-title — 헤더 문구
CSS는 widget.js가 자동으로 불러오므로 별도 link 태그 불필요
Code Snippets 플러그인이면 이 코드를 the_content 필터에 붙이는 PHP 스니펫으로 감싸야 합니다:

php
add_filter('the_content', function($content){
    if (is_single() && in_the_loop() && is_main_query()) {
        $widget = '<div id="tbw-widget"></div>'
            . '<script src="https://당신프로젝트.pages.dev/widget.js" '
            . 'data-container="tbw-widget" data-title="함께 보면 좋은 글" '
            . 'data-max="10"></script>';
        return $content . $widget;
    }
    return $content;
});
